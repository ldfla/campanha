# Relatório financeiro simulado

`GET /financial/campaigns/{campaignId}/reports?from=<instante>&until=<instante>` consulta uma campanha DEMO usando instantes ISO 8601. O intervalo é `[from, until)`, limitado a 366 dias. O acesso exige sessão e vínculo ativo na organização com papel FINANCE, CAMPAIGN_MANAGER ou SYSTEM_ADMIN; campanhas fora de DEMO são bloqueadas.

Os totais usam contagem e centavos BRL. Pedidos usam `created_at`; cobranças MOCK, `created_at`; pagamentos MOCK confirmados, `confirmed_at`; estornos concluídos de pagamentos MOCK, `completed_at`; lançamentos associados a pedidos DEMO com pagamentos apenas MOCK/BRL, `posted_at`. O campo `refundLedgerPosted` é um subconjunto negativo do ledger, não uma soma adicional. Não é correto esperar igualdade entre categorias de períodos em que eventos ocorreram em datas diferentes. Os totais podem revelar diferenças para investigação, mas não constituem conciliação com uma fonte externa nem prova de caixa real. Eventos de estorno recebidos sem registro em `refunds` não aparecem na categoria de estornos concluídos, mas são visíveis no subtotal de estornos do ledger; a ausência do registro em `refunds` permanece pendente de correção no P09.

`GET /financial/campaigns/{campaignId}/reports/export?from=...&until=...` entrega os mesmos totais em CSV UTF-8. Células são delimitadas por aspas, aspas internas duplicadas e conteúdos com prefixos interpretáveis como fórmulas ou controles iniciais recebem apóstrofo. Os valores negativos também recebem apóstrofo e são texto no CSV; a API JSON mantém o valor numérico. Cada exportação autorizada registra ator, campanha e hash do conteúdo na auditoria, sem gravar nomes, telefones ou dados da cobrança.

O relatório opera apenas sobre o subconjunto simulado descrito. Não representa operações reais, prestação de contas definitiva, conformidade fiscal ou autorização para cobrança. A implementação de reconciliação por transação e relatórios consolidados por organização continua pendente.
